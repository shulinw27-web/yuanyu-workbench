# 个人与企业版本

日期：2026-11-06（2026-11-13分支改名）。个人版公共仓库为 [shulinw27-web/yuanyu-workbench](https://github.com/shulinw27-web/yuanyu-workbench)，`main`与`personal`提供个人开源版；企业版仍仅保留在本地，不上传此公开仓库。2026-11-13按用户要求把本地`codex/personal`改名为`personal`、`codex/enterprise`改名为`enterprise`，两个独立根提交历史不变；远程原有的`codex/personal`是改名前的历史别名，不再更新。

| 分支 | 用途 | 源码范围 | 授权与发布 |
| --- | --- | --- | --- |
| `personal` | 个人独立开源版 | 完全本机运行：自配模型接入、本机浏览器与Skill、合成演示、项目管理、多模态附件；无账号/服务端/公网 | MIT；发布至上述个人公共仓库 |
| `enterprise` | 企业版开发基线（独立历史） | 个人基础能力及企业OIDC身份、HTTP模板共享适配器 | 未授予开源许可（package为UNLICENSED）；未来使用独立私有仓库 |

企业版的生产OA、跨机器授权共享等仍按PLAN逐项验收，属于独立历史分支，不属于本公共仓库的现行产品。两个分支不是已经上线的SaaS产品。个人版中保留的Mock公司目录和分享校验只验证合成契约，不授予真实企业权限。

## 历史隔离与协作

个人版与企业版从独立根提交建立；个人版发布时保留GitHub仓库原有README初始化提交，但不会通过任何共同祖先带出企业适配器。不要将企业分支合并到个人分支，也不要把企业提交作为个人分支的父提交。需要同步通用修复时先检查差异，选取允许公开的文件或补丁，再分别提交；未审查的企业改动不能直接移入个人版。

公开仓库内的分支无法分别设置公开/私有。后续发布个人版应使用独立公共仓库并仅推送`personal`；企业版使用独立私有仓库。不要运行`git push --all`或`git push --mirror`，不要将本地`.git`目录连同企业历史一起公开。

## 开源范围

个人分支不包含`src/identity/`、`src/sharing/`及对应企业专项测试；2026-11-18 起进一步移除 `src/product/`、`src/service/`、`deploy/`、`docs/OPERATIONS.md` 及账号相关测试，收敛为完全独立本机 Agent。模型 API 密钥由用户自配、经 OS 加密存于本机仓库外，不写入 Git；无服务端密钥或账号数据库。

MIT许可针对个人分支中由本项目提供的源码；第三方依赖保持其原有许可证。`package.json`的`private:true`只用于阻止误发npm，并不改变个人版MIT许可。便携包会包含本分支存在的LICENSE文件。

`node_modules`、`output`、运行数据、数据库、密钥、证书、模型配置和个人配置均不纳入版本管理。`.workbuddy/`是本机工作记录，也不纳入公开仓库。`.gitignore`只是防误加措施，提交前仍须检查暂存区。

## 个人版推送范围

本地origin指向上述公共仓库。仅推送`personal`到远程`main`与`personal`，两者为同一份个人源码；`enterprise`只在本地保留。远程已有的README初始化提交通过合并保留，不使用强制推送覆盖。每次推送用简短中文提交信息说明本次改动内容。
